# dsh-agent-mesh card UI — first-run wizard, structured status, model roster

Scope: `packages/dsh-agent-mesh/src/client/index.tsx` (only client file touched),
plus tests: new `tests/client-ui.test.ts`, race fix in `tests/task-persistence.test.ts`.
No host/remote changes; every view derives from the existing `MeshWebApi` methods.

## 1. First-run wizard (`WizardSection` rewrite)

`WizardSection` moved out of the collapsed "Mesh node" details to the top of the
settings card, and is now a guided 4-step checklist instead of the raw
`sam-mesh doctor` dump. Steps are derived from live state polled every 4 s
(`nodeStatus`, and when running: `fleetDiscover` + `pairRequests` + `snapshot`,
all `Promise.allSettled` so a failed probe degrades, never blanks the card):

1. **Node installed & enrolled** — from `nodeStatus().installed/.enrolled`.
   Missing binary: inline error + fix (install / pick a binary in Settings).
   Unenrolled: one "Begin enrollment (approved)" button using the existing
   enrollment remotes (`beginEnrollment` / `enrollmentStatus` polling at
   1.5 s / `activeEnrollment` resume on mount / `cancelEnrollment`). Device
   flow shows the verification URL and user code **prominently** (large,
   letter-spaced) with copy buttons each and a live "Waiting for approval…"
   status; failure/cancel renders inline with fix text and a "Try again" button.
2. **Node running** — one "Start node (approved)" button; failures inline with
   the terminal fix hint.
3. **Joined a fleet** — done when (i) a join completed in the embedded
   `JoinFleetSection` flow (new optional `onJoined` callback), (ii) the node's
   own peer id (`snapshot.mesh.router_peer_id`) appears in a discovered fleet's
   `peerIds`, or (iii) `pairRequests().pairing` shows this machine hosts a fleet.
   The current step embeds the full discover → request → waiting → complete
   `JoinFleetSection` flow as its action area.
4. **Capability ready** — `fleetDiscover` answered and at least one of: fleets
   visible, mesh peers > 0, models visible. Otherwise guidance text + "Re-check".

Each step is one line with ✓ done / → current / ○ pending; exactly one primary
action on the current step. When all four are done the wizard collapses to a
single expandable line: "✓ On the mesh — N peers, M models".

The step derivation is a pure exported function (`wizardSteps(facts)`), unit
tested without a DOM. `NodeSection` lost its duplicated enrollment UI (the
wizard owns enrollment now) and keeps pairing/fleet-admin queues and
start/stop lifecycle.

## 2. Structured status

`snapshot.services` / `.tools` / `.models` no longer render as raw JSON
`<details>`. `ChipSection` renders compact chip lists (name + one-line meta via
the defensive pure `chipView`), with the raw JSON behind an "advanced — raw
JSON" details. Failures/tasks/logs keep raw rendering. Data source unchanged
(snapshot probes).

## 3. Model roster with serve state

`ModelRoster` (pure view-model `groupModels(models, serve)`): groups models by
serving peer from `owned_by` when the snapshot carries it (falls back to a
single "mesh" group when absent — no invented fields), labels a group
"(this machine · announceName)" when every model in it is served by the local
serve row, and badges locally-served models from `inferenceServeStatus()`:
`starting → ● warming`, `serving → ● live`, `error → ● error`. Raw JSON stays
behind the advanced details.

## Test-count race fix (pre-existing)

`tests/task-persistence.test.ts` closed the SQLite store while the
auto-started background execution was still writing → unhandled
"database is not open" rejection → vitest exit 1 at baseline. Fixed with
`autoStart: false` (durability assertion doesn't need execution).
